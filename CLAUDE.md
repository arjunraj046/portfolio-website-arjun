# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Quality bar

The owner wants everything built here to be professional, production-standard work: the look and feel of a polished senior developer's portfolio. Every change should meet all of these:

- **Responsive:** works from 360px phones to wide desktops, with no horizontal scroll. Check the `md` and `xl` breakpoints this codebase uses.
- **Light and dark mode:** style both. Use the theme tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `border`) rather than hard-coded colours, unless a colour is decorative.
- **Accessible:**
  - Use semantic elements (`header`, `nav`, `main`, `footer`, `h1`â€“`h3` in order).
  - Give icon-only controls an `aria-label`. Mark decorative elements `aria-hidden`.
  - Keep visible focus states and enough contrast.
  - Open external links with `target="_blank" rel="noopener noreferrer"`.
- **Motion:** keep it subtle and purposeful (roughly 200â€“700ms, ease-out), and disable it when `prefers-reduced-motion` is set.
- **Consistent:** reuse the existing pieces (`Button` variants, `Nav` `links`, `Socials`, `.card-surface`) rather than making one-off copies. Match the existing spacing, softly rounded shapes and type scale.
- **Real content only:** no lorem ipsum and no made-up claims, numbers or testimonials. If a fact isn't available (location, availability, project details), ask the owner instead of guessing.
- **Clean code:** no leftover `console.log`, no dead code, and clean up event listeners. Keep everything that runs in the browser inside client components.
- **No code comments (owner's rule):** the owner had every comment removed from the codebase. Don't add comments to JS, JSX, CSS or config files; the explanations belong in this file instead.
- **SEO-friendly:**
  - Every route exports `metadata` (a unique `title` and `description`; add Open Graph tags when there's a share image).
  - Exactly one `<h1>` per page. Descriptive link text and `alt` text.
  - Keep real text as HTML, not baked into images or canvas, so search engines can read it.
  - Prefer server components and static rendering, so content is in the first HTML response.
- **Fast loading, nothing heavy:**
  - Use `next/image` for images, sized to how they're displayed. Prefer SVG, WebP or AVIF, and keep raster images under ~200 KB. Only above-the-fold images get `priority`.
  - Use `next/font` for fonts. Don't add Google Fonts `<link>` tags or large icon fonts.
  - Don't add videos, large Lottie/JSON animations or big libraries without asking. Use CSS, requestAnimationFrame or IntersectionObserver rather than an animation library (see Stack).
  - Import icons one at a time (`import { SiReact } from 'react-icons/si'`), never a whole icon set.
  - Load heavy, below-the-fold or browser-only pieces lazily with `next/dynamic` (as the hero Lottie does). Keep `'use client'` on the smallest component that needs it.
  - After a build, check the "First Load JS" column in the `next build` output. The home page is currently ~101 kB, `/projects` ~102 kB and `/contact` ~112 kB; don't let changes grow them without a good reason.
- **Smooth, no waiting (owner's rule):** every page should flow smoothly. Don't add artificial delays. Page transitions and component entrance animations should finish within about 300ms, and content must show straight away rather than waiting on an animation.
- **Must not look "vibe coded" (owner's rule):** no em dashes anywhere in site text, titles or images (use a comma, colon, brackets, " | " in titles, or "to" for ranges); no emoji icons; no fake reviews, testimonials, metrics or customer counters; no vague hero or heading copy; no AI-generated photos or filler copy; no "made with AI" tags. Also no purple or violet (the accent is one deep green), no cursor-following effects (the mouse/gyro card tilt, hero icon parallax, sphere cursor tilt and the count-up stats were removed on 2026-10-10 for this reason) and no heavy scroll animation. What stays, deliberately: smooth mouse-wheel scrolling, the 300ms reveal-on-scroll, the gentle CSS drift of the hero icons and the divider streak.
- **Launch checklist (owner's rule):** don't call the site launched until it has a custom domain connected, a favicon, no "made with AI" tag, and the Privacy Policy and Terms pages.
- **Verified:** the build must pass before calling work done (use the `.next-check` build below).

## Commands

- `npm run dev`: dev server at http://localhost:3000
- `npm run build`: production build into `.next`. Building is the only automated check; see below for how to run it safely.
- `npm start`: serve the production build

There is no test framework. `npm run lint` (`next lint`) is wired up, but there is no ESLint config or `eslint` dependency, so it will try to start an interactive setup. Don't rely on it.

**Never run a plain `next build` while the owner's dev server may be running.** Both use `.next`, and the build overwrites the dev server's files, so the running site starts returning 500s for its JS chunks. To check that the code compiles, build into a separate folder instead:

```bash
NEXT_DIST_DIR=.next-check npx next build     # bash
$env:NEXT_DIST_DIR='.next-check'; npx next build   # PowerShell
```

If the dev server does break (500s on `/_next/static/chunks/*`, or "Failed to read source code" after files were moved): stop it, delete `.next`, and run `npm run dev` again. A `ChunkLoadError` on `localhost:3001` (or any port other than 3000) means a second `npm run dev` started while another was still running: both write to `.next` and delete each other's chunks. Stop every dev server, delete `.next` and start just one. The hover prefetch in `Radio` and `MobileNav` catches failed chunk loads (`prefetch`), so a failed background load never shows an error; the real load happens again on click.

## Stack

Next.js 14 App Router in plain JavaScript/JSX (no TypeScript), React 18, Tailwind CSS 3 and shadcn/ui (`components.json`: JSX, RSC on, CSS variables). The `@/*` import path maps to `src/*`.

**No animation library runs on the live pages.** framer-motion, GSAP and Swiper have been uninstalled, along with the unused Expertise section. A speed pass removed them: the home page went from 159 kB to 122 kB First Load JS, and to 101 kB after a second pass (server-rendered sections and hero icons, desktop-only sphere, lazy mobile menu). Keep it that way. Use CSS (keyframes, transitions, tailwindcss-animate), `requestAnimationFrame` and IntersectionObserver instead:
- nav active highlight: CSS `animate-in fade-in` (no framer `layoutId`)
- hero icon drift and sphere "breathe": CSS keyframes in `globals.css` (`.icon-float`, `.animate-hero-breathe`); `FloatingIcons` is a server component with no client code at all (its SVGs are HTML, and the drift is CSS). Don't import `react-icons/si` in a client component that loads with the page: webpack bundles every `si` icon used anywhere in client code into one shared chunk, so it would pull in all the sphere's icons too (it cost ~20 kB)
- `TechSphere`: its own rAF loop with a 60fps frame ratio
- reveal-on-scroll: `shared/Reveal.jsx`, a small client wrapper whose IntersectionObserver toggles `.reveal-pending` on `[data-reveal]` cards, and only on cards below the fold, so nothing on screen is ever hidden

## Architecture

### Folder structure

```
src/
  app/                    routes only: layout, template, page.jsx per route (+ metadata)
  components/
    layout/               site chrome: Header, Footer, Logo, Nav, MobileNav (+ MobileSheet),
                          ThemeToggler, ScrollProgress, SiteBackground, BackToTop, Radio (+ RadioPanel)
    sections/<section>/   one folder per page section, holding the section and its sub-parts
                          (hero/, about/, experience/, projects/, contact/, legal/)
    shared/               small pieces reused across sections (Socials, Reveal, SectionParts, SectionDivider)
    providers/            context providers (ThemeProvider)
    ui/                   shadcn/ui primitives only; add new ones with the shadcn CLI
  data/                   all site content as plain JS: site.js (name, role, CV link, nav links,
                          socials), about.js, experience.js, legal.js, projects.js, radio.js, skills.js
  lib/utils.js            `cn()` class merger
```

Rules for new code:
- **Content goes in `src/data/`, not in components.** Components import it and only handle layout. When the content changes (a new job, a new social link), edit the data file. Facts must come from the owner's resume, never be made up.
- A new page section gets its own `components/sections/<name>/` folder. Only move something to `shared/` once a second section needs it.
- Import across folders with `@/â€¦`; import files in the same folder with `./â€¦`.
- Only `ui/` uses lowercase filenames (the shadcn convention). Everything else is PascalCase.

## Styling conventions

- Theme colours are HSL CSS variables in `src/app/globals.css` (`:root` and `.dark`), exposed through `tailwind.config.js`. Redesign of 2026-11-12 (owner found the blue glass look too common): warm paper background (`45 30% 96%`) and near-black green ink in light mode, deep green-black (`160 18% 6%`) in dark mode, and one accent, `brand` (deep green in light, mint in dark), used for eyebrows, the active nav underline, dots, the divider and text selection. Use `text-brand`/`bg-brand`, not sky or blue. Dark mode is class-based.
- Accessibility baseline (2026-11-12): the layout has a skip-to-content link, and every page's `<main>` has `id="main"`. A global `:focus-visible` rule in `globals.css` draws a 2px `ring`-coloured outline on anything that doesn't set its own ring, so plain links (nav, footer, socials) show keyboard focus. Every link and button is at least 24px tall and wide (WCAG 2.2 target size): footer links get `py-1`, the hero socials are 36px boxes, the carousel dots sit in 24px buttons. Lighthouse couldn't be installed here (npm download blocked), so the checks were done with a headless-Chrome script over the DevTools protocol: LCP, CLS and long tasks via PerformanceObserver, DOM checks for alt text, names, heading order, labels, landmarks and target sizes, and overflow at 360 to 1920px. The Mozhi chat widget loads with `next/script` `strategy="lazyOnload"`, so it never competes with the page's own load. Text colours were checked at WCAG AA (4.5:1) in both themes; form fields use the darker `--input` token so their outlines reach 3:1. `openGraph.locale` is `en_US`. The owner asked for UI changes only: don't reword site copy (projects, legal pages) as part of design work.
- Fonts (`next/font`): IBM Plex Sans for text (`font-sans`) and JetBrains Mono for small labels (`font-mono`: eyebrows, nav, badges, logo monogram).
- Editorial layout, no cards (owner's request, 2026-11-12: "card per section" looked like a million other portfolios). Sections, the footer, the contact page, the project index and each project are laid out as ruled rows: a 1px `border-border` line between items, mono labels on the left and content on the right (`Row` in `SectionParts`), with whitespace instead of boxes. Boxes remain only where something needs an edge: form inputs, the gallery frame (`ImageCarousel`), the radio button and panel, and the mobile sheet. Those use `.surface` / `.surface-raised`; `.site-header` is a plain full-width bar with a bottom hairline. No glass, no backdrop blur on content, no blurred glow blobs, no white rim borders or inner highlights. The old `.glass*` and `.card-surface` classes and `SectionGlows` were removed. The background (`SiteBackground`) is flat paper with a faint grid fading out downward.
- Corners are crisp (the owner asked for sharper edges everywhere): the radio panel uses `rounded-xl` (12px); medium pieces (CTA buttons, the gallery frame, the photo) use `rounded-lg`; small pieces (buttons, inputs, the logo monogram, thumbnails) use `rounded-md`. Only dots and the radio button are `rounded-full`. Surfaces use a 1px `border-border` hairline and almost no shadow. Don't go back to `rounded-2xl`/`3xl` or big soft shadows.
- Buttons (`ui/button.jsx`) are rectangles with small rounded corners, never pills: `rounded-md` by default, and `rounded-lg` for `size='cta'`, the standard call-to-action size. The owner rejected glass, gradient and pill buttons and chose a minimal solid style: `default` is solid, and `outline` is transparent with a thin border. Other controls use the same shape (nav, icon buttons, badges), except the decorative circles.
- The header has no CTA button (the owner removed "Hire me"); the Contact nav link does that job. The CTAs are in the hero ("Contact me"), the footer ("Hiring, or have a project in mind?" with "Get in touch") and the mobile menu ("Contact me"). The contact page's h1 is "Get in touch".
- Cards don't tilt or move with the mouse or the phone's gyroscope. That effect (`TiltCard`, `lib/gyro.js`) was removed for the "not vibe coded" rule, so don't bring it back.
- Sections are separated by `shared/SectionDivider.jsx` (owner's choice): a 1px line fading in from both ends with a brand-green centre and a streak of light running along it in a seamless CSS loop (`.divider-spark`). The owner removed the blurred glow: keep it to the line and its movement. It sits between the hero and About, between projects, and at the top of the footer, so every page has one before the footer.
